# Пошаговый roadmap

База: **0.3.3**, `6910579`, рабочая демка M3. Наличие 20 названий и 3D-прототипа
не закрывает M5/M9. Исходные ID сохранены в [TASKS.md](TASKS.md).
Порядок ниже — по зависимостям; даты до приёмки не обещаются.

## Последние уточнения пользователя — обязательная приёмка

1. Эталон — **C «Панорама»**. Не заменять его произвольным новым меню.
2. Маленькое **ARTEM** над основным **Train Emulator**; расшифровка:
   Artificial Realistic Train Emulator with Modifications.
3. Нейтральный минималистичный **графит везде**, вместо синего фона.
4. Украинский шрифт в духе «Дії»: проверить e-Ukraine, лицензию и воспроизводимую
   загрузку; не коммитить OTF в обход исчерпанного LFS.
5. Свой векторный железнодорожный знак с мотивом Укрзалізниці. По последнему
   уточнению знак — **едва заметная подложка**, не часть строки. ARTEM стоит
   строго над словом Train, оба текста начинаются на одной вертикали.
6. Убрать смысловой повтор «До рейсу»: заголовок остаётся, верхняя правая кнопка
   **«Почати поїздку →»**. Запуск под навигацией, а не в нижнем селекторе.
7. Селектор рейса ограниченной ширины; сегменты 4/6/**8**/10, цветовые образцы,
   без нижней строки подсказок. Справка и переназначения только в «Керування».
8. Выровнять состав в предпросмотре: крупная передняя кабина слева, вагоны вправо,
   правильное число и окраска; довести FOV/focal point, материалы, нос и детализацию
   до эталона. **Качество модели пока не соответствует концепту — пункт открыт.**
9. Проверить украинские слова меню/тумблеров/станций и ТТХ; не выдавать estimates
   за подтверждённые значения (LANGUAGE_AND_SPEC_AUDIT.md).
10. Сохранить исходники, исследования, известные дефекты и проверки в коммитах;
    HANDOFF_CLAUDE.md должен позволять продолжить без потери предыдущих запросов.

Уточнения выше заменяют только соответствующие дизайнерские решения ниже.
Остальные пожелания остаются: непрерывный звук/затухания, реалистичная физика,
оптимизация/HiDPI/развёрнутое окно, отсутствие стартового кадра с путей,
вывески вместо висящих названий, реальные стороны платформ 2–3 станций,
встречный путь/оборот и ещё 2–3 серии с 5–6 окрасками каждая.

## Далее: достоверность демки

0. **R0 — дополнительные серии и окраски (следующий этап по запросу пользователя).**
   Подобрать 2–3 серии (кандидаты ЕР9П, ЕД9М, ЕПЛ9Т) по фото/чертежам с лицензией;
   для каждой отдельно кузов, нос, окна, тележки, приборка и данные. Собрать
   5–6 настоящих схем окраски с ссылками/датой, затем реализовать выбор серии,
   состава и окраски. Приёмка: узнаваемые отличия в одинаковых ракурсах, реальные
   параметры либо явно отмеченные оценки; это не перекрашенные копии ЕР9М.
   Для текущего ЕР9М уже подобраны три дополнительные палитры по сетевым фото.
   **Статус (codex/desktop-demo):** добавлены ЕД9М, ЕПЛ9Т и ЕКр1 «Тарпан» —
   свои вагоны, составы (ЕКр1: 3/6), тяга/масса/скорость, контролер (ЕПЛ9Т 0–6,
   ЕКр1 0–100 %), по 6 окрасок, параметризованный нос (`visual.nose`), выбор серии
   в меню, шкала спидометра по серии. Все данные — оценки `verified:false`;
   окраски ещё без ссылок на фото, тележки и интерьер кабины общие с ЕР9М.
   Не закрыто: источники ТТХ/окрасок, отдельные пульты по посібникам серий.

0a. **P0 — производительность (запрос пользователя).** Сделано (D-016): стриминг
   пути/платформ вокруг поезда, кэш рисованных панелей, петли тифона/свистка без
   перезапуска. Физика измерена: 0.2 мс/шаг, от длины линии не зависит. Осталось:
   замер FPS на реальном Mac/Windows (Xvfb не показателен), LOD вагонов вдали,
   пресеты качества (render scale/MSAA уже есть), MultiMesh для мебели платформ.

1. **A1 — звук.** Записать минуту удержания обоих сигналов, отпускания/повторные
   нажатия и разгон. Приёмка: нет OS key-repeat, щелчков границы петли и голодания
   буфера; хвост сохраняется. Для новых записей обязательны лицензия/атрибуция.
2. **V1 — бюджет кадра.** Профили CPU/GPU для 4/6/10 вагонов, общего вида и кабины
   в одинаковом физическом разрешении; таблица времени кадра/draw calls относительно
   0.3.3. LOD и batching не ухудшают колёса вблизи.
3. **P1 — масса и движение.** Сверить разгон/выбег/торможение и подвеску с источниками;
   кривые, стрелки, обратный ход. Приёмка: измеряемые коридоры и отсутствие рывков.
   Полная многотельная модель — отдельное решение после измерений.
4. **C1 — пульт ЕР9М.** Для каждого прибора/органа: фото/руководство, единицы,
   диапазон, место и связь с системой. Добавлять органы вместе с моделью.
   Приёмка: обновлён CAB_AUDIT.md, оценки отделены от подтверждённых данных.
5. **S1 — 2–3 станции.** Караваєві Дачі, Борщагівка, Святошин: OSM-пути/платформы,
   фото, направления. Для каждой — ссылки, ревизия, лицензия, схема сторон и
   неопределённости. Приёмка: платформа вдоль собственного пути со стороны посадки,
   сравнительные ракурсы. Историческая статья не подтверждает сторону платформы.
6. **S2 — встречный путь и оборот.** После S1: граф второго пути, съезды/тупик,
   безопасная смена кабины. Приёмка: поездка в обоих направлениях без телепортации.
   Сейчас второй путь визуальный, без маршрутизации и ИИ.

## M4 — безопасность, последовательно

1. **T4.1:** формат блок-участков → оси состава → занятость несколькими поездами.
   Проверить хвост, границу, обратный ход и сохранение.
2. **T4.2:** таблица показаний → автоблокировка → 3D-светофоры/HUD.
   Поезд впереди даёт корректную последовательность красный/жёлтый/зелёный.
3. **T4.3:** маршруты из стрелок/сигнала → враждебность → замыкание/освобождение
   хвостом. Конфликтующие маршруты и перевод под поездом запрещены.
4. **T4.4:** кодирование АЛСН → локомотивный светофор → тесты переходов показаний.
5. **T4.5:** ЕПК/РБ/таймеры из подтверждённых правил → автостоп.
   Пропуск подтверждения вызывает торможение; сохранение не сбрасывает таймер.
6. **T4.6:** нарушения с источниками правил → журнал → тесты границ/дребезга.
7. **Приёмка M4:** ИИ-поезд на полигоне, сигналы, автостоп; Godot/JS parity,
   играбельная сборка и журнал нарушений.

## M5 — сначала реальный участок

1. **T5.1:** воспроизводимый OSM-импорт, проекция/единицы, происхождение и лицензия;
   сопоставление станций с платформенными путями (после S1).
2. **T5.2:** DEM-профиль → сглаживание → контроль высот и уклонов.
3. **T5.3:** 4–6 остановок: пути, платформы, сигналы, ограничения и ориентиры;
   ручная сверка обоих направлений (после M4).
4. **T5.4:** расписание с датой источника, стоянки/оборот;
   воспроизводимый рейс игрока и встречного ИИ без конфликтов.
5. **T5.5:** расширение до полного кольца после приёмки участка;
   полный круг в обе стороны. Названия/тарифные расстояния не заменяют геометрию.

## M6–M9

1. **M6/T6.1–3:** источники регламента → диалоги с тайм-аутами → ИИ-ДСП/разрешения
   → контроль пропусков. Отправление требует правильного диалога.
2. **M7/T7.1–4:** движок уроков → пять уроков (кабина, запуск, тормоза, сигналы,
   отправление/остановка) → 30 вопросов с источниками → профиль/оценка рейса.
   **MVP здесь:** ЕР9М, 4–6 настоящих остановок, безопасность, переговоры,
   обучение и рейс с оценкой. Текущая демка этот критерий не закрывает.
3. **M8/T8.1–4:** зависимости/совместимость → ресурсы в рантайме → ЕД9М только
   данными → меню модов и воспроизводимая инструкция.
4. **M9:** точные лицензированные модели → кабина 3D → окружение → LOD/стриминг
   → погода/свет. Приёмка: читаемая приборка и измеряемый бюджет кадра.

Для каждой задачи: источник/схема → критерий/тест → код → make check → GUI/профиль
по затронутой функции → TASKS → логический коммит → проверка конкретной сборки.
Изменение core дополнительно требует reference/parity/web.

Последняя правка предпросмотра: весь состав стоит на прямом выставочном пути,
независимом от кривой игрового маршрута. Камера обязана показывать последний
вагон при 4/6/8/10; это проверяется в navigation_regression.gd.
