> Реалистичный симулятор железнодорожного транспорта Украины.
> Старт: **Киевская кольцевая электричка (Kyiv City Express)**, электропоезда **ЕР9М, ЕД9М, ЕПЛ9Т**.
> Ориентир по духу — кабинные симуляторы уровня ZDSimulator / RTS (Russian Train Simulator):
> реалистичная кабина, процедуры, сигналы, переговоры. **Не** аркада и **не** «Train Sim World с камерой сверху».

## 1. Видение продукта

**Одной фразой:** ты садишься в кабину ЕР9М на станции Київ-Волинський, проходишь
процедуру приёмки и запуска, получаешь разрешение от ДСП по радио, едешь по кольцу
по реальным сигналам, останавливаешься у платформ, соблюдаешь ПТЕ — и игра оценивает
тебя как машиниста-инструктора.

### Столпы (pillars) — каждое решение проверяется на соответствие им

1. **Реализм управления.** Каждый тумблер в кабине что-то делает. Неправильная последовательность
   = поезд не поедет (или поедет и будет нарушение).
2. **ПТЕ как игровые правила.** Нормативка Украины (ПТЕ, Інструкція з сигналізації,
   Інструкція з руху поїздів і маневрової роботи, регламент переговоров) — это не «лор»,
   а движок оценки и обучения.
3. **Данные, а не код.** Подвижной состав, маршруты, сценарии, расписания — это файлы данных.
   Базовая игра сама загружается как «мод». Это автоматически даёт мод-систему.
4. **Сначала работает, потом красиво.** 2D/2.5D → 3D. Ядро симуляции не знает, как оно
   отрисовано, поэтому смена графики не ломает физику.
5. **Украинская специфика.** Украинский язык интерфейса (основной), украинская терминология,
   украинские реалии (переменный ток 25 кВ 50 Гц на Киевском узле, реальные станции).

### Что НЕ делаем в первой версии (явно, чтобы не расползлось)

- Вся Украина, метро, грузовые поезда, тепловозы — **после** MVP.
- Мультиплеер — не раньше, чем будет стабильный одиночный режим.
- Голосовые переговоры (распознавание речи) — сначала меню-диалоги, голос потом.
- Внутриигровой «магазин» модов — сначала локальная папка `mods/`.

## 2. Выбор технологий (кратко; подробно — в ARCHITECTURE.md)

| Решение | Выбор | Почему |
|---|---|---|
| Движок | **Godot 4.7.2-stable** (зафиксирован, D-001) | Бесплатный (MIT), без роялти; 2D и 3D в одном движке → переход 2D → 2.5D → 3D без смены стека; встроенная загрузка ресурс-паков = готовая база для модов; лёгкий; экспорт Windows/Linux/macOS |
| Язык | **GDScript со строгой типизацией** (static typing везде) | Нативный для Godot, быстрые итерации, ИИ-агенты хорошо его пишут; если физика упрётся в CPU — горячие участки переносятся в GDExtension (C++/Rust) без изменения API ядра |
| Инструменты данных | **Python 3.11+** (`tools/`) | Импорт карты из OpenStreetMap, рельефа из DEM, валидация JSON-схем |
| Данные | **JSON + JSON Schema** | Читается людьми, моддерами и ИИ; валидируется в CI |
| Тесты | Собственный мини-раннер (D-004) + headless Godot в GitHub Actions | Ядро симуляции обязано быть покрыто тестами; без внешних аддонов |
| Ассеты | **Git LFS** для `.glb`, `.png`, `.ogg`, `.wav` | Иначе репозиторий распухнет |

Почему не Unity / Unreal: Unity — лицензионные риски и тяжёлый редактор; Unreal — избыточен
для 2D/2.5D-старта, C++/Blueprints дороже в разработке, огромные билды. Godot закрывает все
этапы (2D → 3D) одним стеком.

## 3. Дорожная карта (вехи)

Каждая веха заканчивается **играбельным билдом** и зелёным CI. Детализация задач — в [TASKS.md](TASKS.md).

### M0 — Фундамент репозитория ✅ (сделано)
- Godot-проект в `game/`, структура папок, автозагрузки (autoload), код-стайл.
- CI: headless-запуск тестов, валидация JSON-данных схемами, линт GDScript (gdtoolkit).
- Git LFS, `.gitignore`, `.gitattributes`.
- **Готово, когда:** `godot --headless` прогоняет пустой тест-сьют в CI, проект открывается в редакторе.

### M1 — Ядро симуляции (без графики) ✅
- Модель пути: граф сегментов (длина, профиль/уклон, кривые, ограничения скорости, электрификация), стрелки.
- Модель поезда: масса, сопротивление движению, сила тяги/торможения, сцепление (адгезия).
- Фиксированный шаг симуляции, ускорение времени, пауза, сохранение/загрузка состояния.
- **Готово, когда:** юнит-тесты проверяют: разгон до 100 км/ч за реалистичное время,
  выбег на уклоне, тормозной путь в допустимом коридоре, детерминированность (одинаковый вход → одинаковый выход).

### M2 — Тестовый полигон (2D) ✅ (+ веб-превью)
- Синтетический участок ~10 км: 3 станции, 2 перегона, уклоны, кривые.
- Вид сверху (2D-схема пути с поездом), отладочный HUD (скорость, давления, сила тяги, позиция).
- Управление с клавиатуры: контроллер машиниста, кран машиниста.
- **Готово, когда:** можно доехать от станции А до станции Б и остановиться у платформы.

### M3 — Кабина ЕР9М (2.5D)
- 2.5D = интерактивный 2D-пульт машиниста (кликабельные тумблеры, стрелочные приборы)
  поверх простого 3D-вида вперёд (процедурный путь, шпалы, столбы контактной сети, светофоры-«коробки»).
- Конечный автомат систем поезда: приёмка → подъём токоприёмника → включение ГВ →
  вспомогательные машины → зарядка тормозной магистрали → проба тормозов → готов к отправлению.
- Базовые звуки (компрессор, тяговые двигатели, тормоз, двери).
- **Готово, когда:** «холодный» поезд можно запустить строго по процедуре, ошибки процедуры детектируются.

### M4 — Сигнализация и безопасность движения
- Светофоры (входные, выходные, проходные, маневровые), автоблокировка, сигнальные показания по
  Інструкції з сигналізації.
- АЛСН (локомотивный светофор), ЕПК + рукоятка бдительности (РБ), автостоп.
- Ограничения скорости (постоянные, временные — «предупреждения»).
- Детектор нарушений: проезд запрещающего сигнала, превышение скорости, проезд платформы, жёсткое торможение.
- **Готово, когда:** на полигоне работает автоблокировка с другим (ИИ-)поездом впереди и все нарушения фиксируются в журнале.

### M5 — Киевское кольцо (первый реальный маршрут)
- Импорт геометрии из OpenStreetMap (`tools/osm_import`), профиль из DEM, ручная доработка.
- Реальные станции и остановочные пункты кольца, платформы, расписание городской электрички.
- Начать с **одного участка** кольца (~15–20 км), затем замкнуть кольцо целиком (~50 км, ~20 остановок).
- **Готово, когда:** можно проехать рейс по расписанию по реальному участку.

### M6 — Переговоры и диспетчеризация
- Регламент переговоров: машинист ↔ ДСП, машинист ↔ ДНЦ, машинист ↔ помощник.
- Сначала — меню выбора реплик (как в ZDSimulator), с проверкой правильности формулировки и порядка.
- ИИ-ДСП: готовит маршруты, открывает сигналы, выдаёт предупреждения; ИИ-поезда по расписанию.
- **Готово, когда:** отправление со станции невозможно без корректного диалога, ошибки регламента штрафуются.

### M7 — Обучение и карьера (MVP-версия)
- Режим «Навчання»: интерактивные уроки (знакомство с кабиной, запуск, торможение, сигналы).
- Теория ПТЕ: банк вопросов-тестов.
- Карьера: профиль, рейсы, оценка за рейс (пунктуальность, безопасность, плавность, регламент), допуски.
- **Готово, когда:** новый игрок проходит обучение и получает допуск к первому «настоящему» рейсу.

### M8 — Мод-система (публичная)
- Загрузка модов из `user://mods/` и `mods/`: манифест, версия API, зависимости, порядок загрузки.
- Типы модов: подвижной состав, маршруты, сценарии, ливреи, звуки.
- Пример мода в репозитории. Документация для моддеров.
- **Готово, когда:** ЕД9М или ЕПЛ9Т добавляется в игру **только** как мод, без правок кода.

### M9 — Переход в 3D
- Модели составов в `.glb`, кабина в 3D, окружение (платформы, вокзалы, деревья, город).
- LOD, стриминг участков маршрута, день/ночь, погода.
- 2D-вид остаётся как «диспетчерская схема» / карта.

### Дальше (после MVP)
- Остальные составы Киевского узла (ЕКр1 «Тарпан», локомотивная тяга ЧС/ВЛ/ДС3 и т.д.).
- Расширение карты: Киев → пригородные направления → магистрали → вся Украина.
- **Метро** (Киевское метро): отдельный модуль — третий рельс 825 В, АЛС-АРС, вагоны 81-717/714 и новее.
- Мультиплеер (машинист + ДСП), голосовые переговоры, мастерская модов.

## 4. MVP (вертикальный срез) — определение

MVP = вехи **M0–M7 в минимальном объёме**:

- 1 состав: **ЕР9М** (полностью проработанный).
- 1 маршрут: участок кольца с 4–6 остановками.
- Полная процедура запуска, АЛСН, светофоры, переговоры с ДСП меню-диалогами.
- Режимы: обучение (3–5 уроков) + свободная поездка + 1 рейс по расписанию с оценкой.
- Украинский интерфейс.

Всё остальное — расширение того же фундамента данными.

## 5. Риски и как их гасим

| Риск | Митигация |
|---|---|
| Нет точных техданных по ЕР9М/ЕД9М/ЕПЛ9Т | Все параметры — в JSON, помечены `"verified": false`; правдоподобные значения на старте, уточнение по мере ресёрча (RESEARCH.md) |
| Нормативка обширная, легко утонуть | Реализуем только правила, которые проверяемы в сценариях MVP; список правил — в SIMULATION.md §6 |
| ИИ-исполнитель «расползается» и переписывает ядро | Жёсткие правила в GEMINI.md, задачи маленькие, тесты на ядро обязательны |
| Производительность физики при многих поездах | ИИ-поезда считаются упрощённо (точечная масса, крупный шаг), детально — только поезд игрока |
| Лицензии карт/моделей | OSM — ODbL (атрибуция обязательна); собственные модели; товарные знаки Укрзалізниці — фан-проект, логотипы — осторожно |
| Переход 2D → 3D ломает всё | Ядро не зависит от отрисовки (ARCHITECTURE.md §3), вид — подписчик на состояние |
