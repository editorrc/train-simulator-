# Журнал архитектурных решений (ADR-lite)

Формат: **ID — решение** · статус · почему · последствия. Новое решение — новая запись внизу;
старые не переписываются, а помечаются `заменено D-xxx`.

## D-001 — Движок Godot 4.7.2-stable, язык GDScript (строгая типизация)
**Принято.** Бесплатный (MIT), 2D и 3D в одном движке, встроенные ресурс-паки для модов.
Версия зафиксирована в `game/project.godot` (комментарий), `.github/workflows/ci.yml` (`GODOT_VERSION`), README.
Обновление движка — отдельной задачей: поднять версию в трёх местах, прогнать `make check`.
Предупреждение `untyped_declaration` = **ошибка** (project.godot) — нетипизированный код не соберётся.

## D-002 — Ядро симуляции без Node, только СИ, детерминизм
**Принято.** `game/core/` — `RefCounted`-классы. Не используют сцену, ввод, автозагрузки, `randf()`.
Шаг фиксированный `SimConfig.SIM_DT = 1/60 с` (`FixedStepClock`). Причина: тестируемость в headless,
повторы поездок, смена 2D→3D без изменений физики, будущий мультиплеер.

## D-003 — Единицы в данных: суффикс в имени ключа
**Принято.** В JSON единицы пишутся в имени поля: `length_m`, `speed_kmh`, `mass_empty_t`,
`pressure_kgf_cm2`, `permille`. Загрузчик (`from_dict`) сразу конвертирует в СИ через `Units`.
Почему: данные удобно писать в привычных ж/д единицах (так их пишут в документах), а в ядре нет путаницы.

## D-004 — Собственный минимальный тест-раннер вместо GUT/gdUnit4
**Принято.** `game/tests/run_tests.gd` (≈80 строк) + `TestCase`. Ловит ошибки скриптов через `Logger`
(Godot ≥ 4.5), поэтому упавший посреди теста код = провал, а не ложный «ok».
Почему: ноль внешних зависимостей, нет рассинхрона версий аддона с движком, ИИ-агентам проще.
Если понадобятся моки/параметризация — пересмотреть (кандидат: gdUnit4).

## D-005 — Топология пути: сегменты с концами A/B + узлы end/joint/switch
**Принято.** Сегмент меряется от конца A (offset 0) к B. Узел связывает концы сегментов:
`end` (1), `joint` (2), `switch` (trunk/straight/diverging + state). Позиция = сегмент + offset + направление.
Проход противошёрстной стрелки — по её положению; пошёрстной, поставленной не под поезд, — событие
`switch_trailed` (взріз), поезд проходит, правило ПТЕ фиксирует нарушение.
Уклоны в данных — со знаком для движения A→B.

## D-006 — Базовая игра = мод `base`; данные проверяются схемами в CI
**Принято.** `game/content/base/mod.json`. Каждый `*.json` в мод-папке обязан иметь схему
(`tools/validate_data.py`, правила `SCHEMA_RULES`), иначе CI красный. Плюс перекрёстные проверки ссылок
(ноды↔сегменты, платформы, составы, сценарии). Моды в MVP — только данные и ресурсы, без скриптов.

## D-007 — Значения-заглушки помечаются `meta.verified: false`
**Принято.** Любое число, не подтверждённое источником, живёт в данных с `meta.verified: false`
и `note: "TODO_SOURCE ..."`. Позже UI разработчика может подсвечивать непроверенные данные.

## D-008 — Веб-превью: порт ядра на JS со сверкой по эталонной траектории
**Принято.** `web_preview/sim.js` — построчный порт `game/core` для просмотра в браузере (страница
`web_preview/index.html`, собирается `tools/build_web_preview.py`, данные встраиваются). Источник правды —
GDScript. Сверка: `game/tests/parity/parity_script.json` (сценарий команд) → Godot пишет
`parity_reference.json` → `web_preview/parity_check.js` требует совпадения до 1e-9 м/с.
`test_parity.gd` падает, если физика в GDScript изменилась, а эталон не перезаписан.
Почему не экспорт Godot в Web: wasm ~35+ МБ, не помещается в ограничения артефактов и медленно грузится;
к экспорту вернёмся для полноценной веб-версии игры.

## D-009 — Простые модели тяги и тормозов до M3
**Принято.** Тяга: `F = min(доля_силы·Fmax, доля_мощности·Pmax / v)` с плавным нарастанием и ограничением
по сцеплению (боксование). Тормоз: «спрос на торможение» 0..1, положения крана задают действие
(отпуск / перекрыша / торможение) и темп — в данных состава (`brake_valve.model = "simple"`).
Это заглушки с правдоподобным поведением; в M3 их заменяют пневматика и электрика без смены API `Train`.

## D-010 — Силы считаются по каждому вагону; стрелка под поездом замкнута
**Принято.** Уклон, кривая и ограничение скорости берутся в центре каждого вагона (проход назад от головы по графу).
Перевод стрелки, на которой стоит поезд, отклоняется (`SimWorld.set_switch`). Поэтому обход графа назад
от головы всегда совпадает с реальным путём состава. Движение назад ведёт хвост (`Train._move`).

## D-011 — 2.5D-вид: ортографическая проекция с поворотом и наклоном камеры
**Принято.** `views/side/rail_view.gd`: x — кілометраж, y — поперёк пути, z — высота. Пресеты камеры
(3/4 спереди, сбоку, 3/4 сзади, сверху), клавиши C, [ ], PageUp/PageDown. Грани вагона рисуются аффинными
преобразованиями (`TrainPainter`). Без декораций: один вид для магистрали и метро.

## D-012 — Плавающие панели и процедурный звук
**Принято.** Все окна, кроме сцены, — `FloatingPanel` (перемещение, размер, сворачивание, прилипание; раскладка
в `user://ui_layout.cfg`, F10 — сброс). Звуки синтезируются в коде (`audio/synth.gd`).

## D-013 — Публикация на GitHub Pages
**Принято.** `.github/workflows/pages.yml` экспортирует игру в Web (Compatibility, без потоков) и кладёт рядом
веб-превью. Разовая настройка: Settings → Pages → Source: GitHub Actions.
